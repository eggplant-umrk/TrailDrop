# 公開デモ環境

TrailDropの公開デモは、FrontendをVercel、BackendをRender、DatabaseをSupabaseで運用する。
実決済は行わず、画面上の決済はモックのままとする。

## 1. 事前確認

- `supabase/migrations/`を古い順にすべて適用する。
- 特にBackend公開前に、`items.is_active`を追加する最新マイグレーションまで適用する。
- 予約作成、キャンセル、QR受取確認をステージング相当のデータで確認する。

## 2. Backend（Render）

Repository rootの`render.yaml`をBlueprintとして読み込む。

Renderへ以下のSecretを登録する。値をGitへコミットしないこと。

| Key | Value |
| --- | --- |
| `SUPABASE_URL` | Supabase Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Backend専用のservice role key |
| `ALLOWED_ORIGINS` | Vercelの公開URL（例: `https://traildrop.vercel.app`） |
| `STAFF_API_TOKEN` | 十分に長いランダム値 |
| `GOOGLE_MAPS_API_KEY` | Google Routes APIを許可したBackend用キー |
| `ROUTE_ANALYSIS_CLIENT_KEY` | Frontendと共有するランダム値 |

`PICKUP_SELECTION_MODE`は、実在する受取地点の座標を確認して`pickup_locations`へ登録するまでは`fixed`を使用する。

デプロイ後、次が200を返すことを確認する。

```text
https://<render-service>.onrender.com/health
```

## 3. Frontend（Vercel）

VercelでGitHub RepositoryをImportし、Root Directoryを`frontend`に設定する。

- Framework Preset: Vite
- Build Command: `npm run build`
- Output Directory: `dist`

環境変数を登録する。

| Key | Value |
| --- | --- |
| `VITE_API_BASE_URL` | Renderの公開URL（末尾の`/`なし） |
| `VITE_DEMO_MODE` | `false` |
| `VITE_ROUTE_ANALYSIS_CLIENT_KEY` | Backendの`ROUTE_ANALYSIS_CLIENT_KEY`と同じ値 |

`frontend/vercel.json`は、`/reserve/...`や`/complete/...`を直接開いた場合もReactへルーティングする。

## 4. CORSの仕上げ

Vercelの公開URLが確定したら、Renderの`ALLOWED_ORIGINS`へそのURLを設定して再デプロイする。
Preview DeploymentもBackendへ接続させる場合は、利用するPreview URLをカンマ区切りで追加する。

## 5. 公開前チェック

1. ルート検索が成功する。
2. 商品を予約できる。
3. 予約完了画面を再読み込みしてもQRが表示される。
4. スタッフ画面でQRを読み取り、受取済みにできる。
5. 未受取予約をキャンセルすると在庫が戻る。
6. 画面に「デモ決済」であり実決済が発生しないことが表示される。

Render Freeでは無通信が15分続くとBackendが停止し、次のアクセス時に起動待ちが発生する。発表直前に`/health`へアクセスして起動しておく。
